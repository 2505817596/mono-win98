mcs/class/System.Windows.Forms/System.Windows.Forms/XplatUIWin32.cs:
decode/encode CF_TEXT with the system ANSI code page.

On Win9x the clipboard holds CF_TEXT in the system ANSI code page (e.g.
936/GBK on Chinese Windows).  AnsiToString used Marshal.PtrToStringAnsi,
whose conversion treats the bytes as UTF-8 on this build and aborts with

    System.ExecutionEngineException: String conversion error:
    Illegal byte sequence encounted in the input.

as soon as non-ASCII text is pasted.  StringToAnsi had the mirror problem
(UTF-8 bytes stored into CF_TEXT).

Both directions now use Encoding.GetEncoding(GetACP()).  This requires the
I18N.CJK.dll assembly (now shipped in lib/mono/4.5) for code page 936.
